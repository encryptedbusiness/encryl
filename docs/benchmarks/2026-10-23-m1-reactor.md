## What is being measured

1. **Reactor path**: accept → multishot poll → one-shot recv into a per-loop
   userspace arena → echo → send, with no WebSocket parsing.
2. **Public path**: WebSocket upgrade → RFC 6455 parse → 16-byte envelope
   decode → handler → `Conn.Send` → command ring → WS frame → send.
3. **Idle density**: 10,000 established WebSocket connections held idle while
   server RSS is sampled.

The reactor stores no callback per file descriptor. Completions carry
`(op, slot, generation)` integers in `user_data` and are dispatched by one
switch. The only function-valued configuration is per loop (`OnOpen`,
`OnMessage`, `OnClose`, `ReleaseSend`, `Logf`), never per connection. A compile
test rejects any function field in `Slot`; the measured slot is **160 bytes**.

Per-connection layout after the M1 memory pass:

| Component | Size |
| --------- | ---- |
| `Slot` (fd, generation, state, 5 timer handles, bids, peer tuple, handshake pointer, optional extra pointer) | 160 B |
| Embedded `ws.Parser` | 64 B |
| Handshake parser | 8 B pointer; parser is pooled and only held while handshaking |
| Optional `connExtra` (large send buffer / pipelined upgrade bytes) | nil unless needed |
| Public `Conn` handle | ~40 B |
| Chunked connection-table entry | 8 B |
| Timer-wheel node | ~32 B |

The earlier design kept the upgrade parser (160 B) and the WS parser's
spill/control slices (48 B) in every slot and allocated an `8 MB` `[]*Conn`
table for the default `MaxConnections`. Both are gone: the upgrade parser comes
from a per-loop pool, the spill/control buffers live in an optional
`parserExtra`, and connection lookup is a chunked table that grows with active
slots. The slab and timer-wheel chunks are also smaller (512 entries).

## Public server echo, 100,000 messages

```bash
go test -run=NONE -bench=BenchmarkServerEcho100k -benchmem -benchtime=100000x .
```

| Metric | Value |
| ------ | ----- |
| Iterations | 100,000 |
| ns/op | 26,506 |
| Round trips/s | ~37,727 |
| B/op | 0 |
| allocs/op | 0 |

The public path includes the upgrade, envelope decode, handler dispatch,
`Conn.Send`, the MPSC command ring, WS framing, and the send completion. Small
outbound messages use a bounded channel buffer pool; the owning loop returns the
buffer after the synchronous copy into the TX arena.

## Room snapshot

```bash
go test -run=NONE -bench=BenchmarkSnapshot1000 -benchmem -benchtime=1000x ./internal/room
```

| Members | ns/op | B/op | allocs/op |
| ------: | ----: | ---: | --------: |
| 1,000 | 6,408 | 12,288 | 1 |

One snapshot allocation per fan-out, never one per recipient. The encoded frame
is shared by every destination loop; it is not refcounted because the commands
keep it alive until processed.

## Idle connection memory, 10,000 connections

```bash
CONNS=10000 DURATION=10s RATE=5000 ./scripts/soak.sh
```

| Metric | Value |
| ------ | ----- |
| Connections attempted | 10,000 |
| Peak active | 10,000 |
| Failed | 0 |
| Baseline RSS | 8,636 KiB |
| Peak RSS | 14,492 KiB |
| Peak delta per connection | **0.59 KiB** |
| Steady RSS after forced GC | 13,560 KiB |
| Steady delta per connection | **0.49 KiB** |
| Slot size | 160 B |

The soak now sends `SIGUSR1` after the ramp; the echo example calls
`runtime.GC()`, and the script records a steady-state sample at 8 seconds while
all 10,000 connections are live. The earlier pre-layout run measured
0.99–1.09 KiB/connection; the reductions above brought the live heap from
11.9 MB to 3.7 MB and the steady delta to 0.49 KiB.

The figure includes the slab entry, the peer tuple, the public `Conn` handle,
the chunked connection-table entry, the idle timer node, and Go heap/runtime
overhead. It does not include kernel socket slabs. Idle connections hold no read
buffer, no write buffer, no goroutine, no channel, and no timer object
(`time.Timer`).

The full 60-minute soak and the Autobahn suite are validation runs, not new
code paths. The Autobahn runner is `scripts/autobahn.sh` and requires Docker on
a host that can run io_uring.
