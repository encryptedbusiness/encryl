# 0016 — Bounded acknowledgements

Status: Accepted
Date: 2026-10-23
Deciders: sairash

## Context

The v2 envelope has a 64-bit `requestID`. The dispatcher already sends an empty
`ACK` when a handler returns nil for a requestID, and an `ERROR` carrying the
same requestID when it returns an error. There was no way for the application to
send a request and receive an acknowledgement, and no way to attach a payload to
a reply.

socket.io's `emitWithAck` is the model: a request carries a correlation ID, the
peer answers, and the caller's callback runs once with the answer or a timeout.

## Decision

### 1. Server-initiated requests: `Conn.Ask` / `EmitWithAckID`

```go
c.Ask("event", payload, timeout, func(a encryl.Ack))
```

The request is an ordinary `EVENT` with a non-zero `requestID`. The peer answers
with `ACK` and the same `requestID`. The callback receives `Ack{Event, Payload,
Err}` and runs **once**: on the ACK, on the timeout, or with an error.

### 2. Replies to inbound requests: `Conn.Reply`

```go
c.Reply(m, payload)
```

`Reply` sends an `ACK` with `m.RequestID` and an optional payload. It sets a
loop-local `replied` bit so the automatic empty ACK is suppressed. Calling
`Reply` for an unsolicited message (requestID zero) is an error.

### 3. The pending slab is bounded

`internal/event.Pending` is a server-wide slab of `Config.MaxPendingAcks`
entries (default 65536). `Bind` returns a token built from `slot<<32 | gen`,
so completion is a direct index, not a map lookup. A full slab returns
`ErrBackpressure`. The slab never grows past its configured bound.

`Bind` also stores the creating connection's identity `(loop, slot,
generation)`. `Take` consumes an entry only when all three fields match, so a
peer that guesses another connection's token cannot run its callback or
destroy its pending entry. A mismatch is counted as a stale ACK and dropped.

### 4. The timeout uses the loop's timer wheel

`Ask` (and the numeric `EmitWithAckID`) enqueues `CmdAckArm{ackSlot, generation, timeout}` to the owning
loop. The generation travels in the command and is stored with the wheel
handle, so a timer that fires for a released and rebound slab entry is
rejected by `Pending.Timeout(slot, generation)`. The loop acquires one wheel
node, sets its owner to the ack slot, and adds it with the ACK timer kind. A
timeout completion calls `Server.handleAckTimeout`, which removes the slab
entry and invokes the callback with `ErrAckTimeout` on the **owning loop**. No
`time.Timer` is created per acknowledgement. If the wheel cannot supply a node,
the arm fails loudly and the entry completes with an error immediately rather
than leaking without a timer.

An ACK envelope cancels the wheel node and invokes the callback inline on the
same loop. `Pending.Take` and `Pending.Timeout` are mutually exclusive under the
slab mutex, so the callback cannot run twice. Every `Ask`/`EmitWithAckID` failure path
after a successful arm enqueues `CmdAckCancel`, so an arm-then-failure cannot
leave a live timer.

### 5. The callback is a loop callback

It runs inline on the connection's loop under the same non-blocking contract as
an event handler. A callback that blocks stalls every connection on that core.

## Consequences

- A request/response API exists without changing the wire format. `requestID`
  was already in every envelope.
- A full slab is visible synchronously: `ErrBackpressure`, no heap growth.
- The ACK path uses the same `Frame` pool, write queue, and admission gate as
  events. A slow peer backpressures an ACK exactly like an event.
- Slab entries outlive a closed connection until their timeout, because the
  slab does not maintain a per-connection list. This is bounded by
  `MaxPendingAcks`. A future change can cancel by connection if the bound
  proves too coarse.

## Rejected alternatives

- **A `time.AfterFunc` per request.** It allocates a timer and a goroutine
  wakeup per request, and it breaks the no-per-connection-timer rule.
- **An unbounded map keyed by token.** It grows without limit and makes a
  request flood an OOM vector.
- **Delivering the timeout callback on the caller's goroutine.** The slab has no
  caller goroutine; the owning loop is the only place the connection state is
  valid.
